# Расширенный архивный GFS эксперимент (отдельная ветка)

## Итог

Новая модель **не обошла** GFS power curve. По декабрю выбрана та же power curve, которая на январском финальном периоде получила MAE **0,266605**, RMSE **0,348941**. Лучшая из проверенных регуляризованных LightGBM имела январскую MAE **0,294887**. Число 0,204392 из исходного MVP относится к другим четырём январским origins, поэтому его нельзя сравнивать с этим результатом как улучшение или ухудшение одной и той же выборки. MAE 0,030807 модели с фактической SCADA-погодой не является оценкой прогноза.

## Данные и временной аудит

* Ветка: `feat/expanded-archived-gfs-model`, отдельный worktree. Backend, его конфигурация и bundle другого окна не изменены.
* Диапазон выбранных origins: `2025-08-04T06:00Z` — `2026-01-26T06:00Z`; 23/23 загружены, 23 GFS cycles, 2 208 строк (48 часов × 2 турбины × 23). По месяцам: август 6, сентябрь 2, октябрь 0, ноябрь 1, декабрь 5, январь 9. Это лишь 23 из 176 возможных ежедневных дат на указанном интервале. Ежедневные серии добавлены 5–6 августа, 1–5 декабря и 6–10 января. Непокрытые даты остаются существенным пробелом; их не следует считать отказами NOAA.
* Для всех 23 origins полный набор 48 GFS объектов и их `.idx` был опубликован к origin по S3 `Last-Modified`; наиболее поздняя доступность предшествовала origin на 1,896–2,052 часа. Snapshot содержит исходные URL, времена, byte ranges и SHA-256. Все сохранённые snapshots и dataset повторно проверяются по хешам до обучения. Для выбранных origins отсутствующих hourly labels нет.
* SCADA CSV заканчиваются 31 января 2026. Часы интерпретируются как `Asia/Almaty`; в label берётся среднее **шести** корректных 10-минутных значений. По всей истории T1: 23 667 полных часов из 25 392 (1 725 неполных/загрязнённых), T2: 24 785 из 25 392 (607). В августе–январе по локальному времени осталось 4 347 часов T1 и 4 341 T2. Часов с мощностью ≤0,02: 1 014/1 070; при наблюдаемом SCADA ветре ≥6 м/с и мощности ≤0,05: 5/16; при мощности ≥0,98: 347/70. Наблюдаемый ветер применён **только для проверки качества labels**, в признаки не входил. Без статусов турбин и команд ограничения мощности нельзя достоверно отделить остановки и curtailment от прочих причин. Эти часы не исключались по эвристике.
* Признаки: только GFS ветер на 100 и 10 м, GFS температура 2 м и производные, известные к origin календарные признаки, lead и ID турбины. Фактические wind/temperature целевого часа отсутствуют. GFS поля относятся к началу целевого часа; label — к следующему часу.

## Хронологическая оценка

Train: origins до 1 декабря, **9 origins / 864 строки**. Подбор: декабрь, **5 origins / 480 строк**. Финальная оценка: январь, **9 origins / 864 строки**. Строка train допускается, только если конец target и предполагаемое время публикации label не позже начала следующего периода; такое же правило применяется к подбору перед январём. Январские ключи `(origin, target, turbine)` одинаковы у всех кандидатов, их SHA-256 записан в `metrics_summary.json`. Кандидат выбран по декабрьской общей MAE до подсчёта январских метрик.

LightGBM сильной регуляризации снижает RMSE относительно curve, но уступает по заранее выбранной MAE. Менять критерий после январского просмотра нельзя.

Публикационная задержка SCADA **неизвестна**. Основное допущение — 0 часов после конца target. При 6, 24 и 48 часах состав этих трёх выборок и refit не меняется из-за расстояния выбранных origins от границ. При стресс-сценарии 72 часа январская оценка и refit теряют по 24 строки (840 и 2 184 соответственно). Это проверка доступности labels, не новая независимая оценка модели.

## Артефакт и запуск

Bundle `artifacts/models/gfs-extended-selected-20260131` имеет существующий backend kind `gfs_power_curve_v1` и прежний входной контракт: `gfs_wind_speed_100m`, `turbine_id`; выход — 96 прогнозов `normalized_power` в `[0,1]` на 48 часов. Backend изменения не требуются. `training_cutoff = 2026-01-30T18:00:00Z`, первый предполагаемый запуск `2026-01-31T06:00:00Z`. `model.txt` SHA-256: `1614e25e62aedb24ae1ff3faaa2ede2c8566ad29ccda7398d38c812bee792853`. Bundle содержит schema, metadata, dataset/source hashes, split, ограничения, метрики и checksums. Загрузка существующим CPU adapter и 96 предсказаний по февральскому **weather snapshot** проверены. Февральских labels нет, февральская точность не измерена.

Январские метрики относятся к кандидату, обученному до января. Экспортированный bundle дополнительно refit на всех 2 208 допустимых до cutoff строках. У **экспортированной версии нет независимой holdout-оценки**; это явно записано в `metrics_summary.json`.

Из корня worktree (Python 3.11–3.13):

```bash
python -m pip install -r ml/requirements-brev.txt -r requirements-weather.txt -r requirements-backend.txt
python -m ml.build_gfs_training_dataset --start 2025-08-04T06:00:00Z --end 2026-01-27T06:00:00Z --origins-file ml/gfs-origins-extended.txt --out-dir data/gfs-training/extended-2025-08-to-2026-01 --workers 8
python -m ml.train_extended_gfs --dataset-dir data/gfs-training/extended-2025-08-to-2026-01 --out-dir artifacts/models/gfs-extended-selected-20260131
python -m pytest tests/test_gfs_training.py tests/test_gfs_model.py tests/test_extended_gfs.py -q
```

Для offline-повтора сборки укажите `--cache-dir data/gfs-training/extended-2025-08-to-2026-01/snapshots` и **другой** `--out-dir`. Файлы snapshot в репозитории фиксируют provenance. Вопрос расширения до всех ежедневных origins остаётся открытым: по сроку хакатона собраны лишь выбранные серии, и оснований заявлять более сильную модель пока нет.
