# Исторический replay погоды

Первый вертикальный сценарий готовит и проверяет погодные входы для прогноза. Он не запускает модель мощности и не создаёт вымышленные значения: успешный результат имеет статус `weather_inputs_ready`, а поле `forecast_power` остаётся `null`.

## Временной контракт

`--as-of` задаёт границу информации симулируемого запуска. Значение должно содержать часовой пояс и попадать на начало часа. Код приводит его к UTC. Горизонт может быть только 24 или 48 часов.

Погодный snapshot проходит проверку, только если:

- время инициализации GFS не позже `as_of`;
- `Last-Modified` каждого GRIB-объекта и его `.idx` не позже `as_of`;
- общее `available_at` равно самому позднему из этих значений;
- есть ровно одна точка для каждой пары «турбина × час»;
- значения конечны, а скорости ветра неотрицательны.

Проверка метаданных и декодирование — разные этапы. HTTP-заголовки доказывают доступность объекта к моменту replay. Поля, время валидности и единицы проверяются по декодированному GRIB-сообщению.

## Офлайн-запуск

Офлайн-режим не обращается к сети:

```bash
python replay.py \
  --as-of "2026-02-06T00:00:00Z" \
  --horizon 48 \
  --snapshot data/fixtures/noaa-gfs-20260206T000000Z-h48.json \
  --output-dir artifacts/replay-2026-02-06
```

## Загрузка из архива NOAA

Для live-режима нужен необязательный пакет `eccodes`:

```bash
python -m pip install -r requirements-weather.txt
python replay.py \
  --as-of "2026-02-06T00:00:00Z" \
  --horizon 48 \
  --cache-dir .cache/weather \
  --output-dir artifacts/replay-2026-02-06
```

Адаптер скачивает индекс и только нужные диапазоны байтов GRIB. Если сервер игнорирует `Range`, отсутствует `Last-Modified` или источник стал доступен позже `as_of`, запуск завершается ошибкой.

## Необязательные SCADA и модель

SCADA принимаются только с явной семантикой: колонка `interval_end` содержит правую границу завершённого часа и обязательный UTC-offset, а задержка источника задаётся параметром. Например:

```bash
python replay.py \
  --as-of "2026-02-06T00:00:00Z" \
  --horizon 24 \
  --snapshot data/fixtures/noaa-gfs-20260206T000000Z-h48.json \
  --scada-csv data/scada.csv \
  --scada-latency-minutes 10 \
  --model-metadata artifacts/model/metadata.json \
  --output-dir artifacts/replay-2026-02-06
```

Строка SCADA доступна в `interval_end + latency`; более поздние строки отбрасываются. Для модели обязательна граница `training_cutoff`, а указанные `data_cutoff`, `preprocessing_cutoff` и `calibration_cutoff` также не могут быть позже `as_of`. Без этих файлов audit честно отмечает SCADA и модель как `NOT_VERIFIED`.

## Пакетное покрытие февраля

Команда ниже проверяет ежедневные точки с 31 января по 28 февраля 2026 года. Час `00:00 UTC` выбран только для демонстрации: рабочий график запуска ещё не согласован.

```bash
python -m scripts.build_weather_coverage \
  --start 2026-01-31 \
  --end 2026-02-28 \
  --origin-hour 0 \
  --horizon 48 \
  --cache-dir .cache/weather \
  --manifest artifacts/weather-coverage.json
```

Результат `weather-inputs-audit.json` хранит `as_of`, реальное время выполнения, погодный выпуск и доступность, URL и хеши использованных диапазонов, фактический cutoff SCADA, статус модели и предупреждения.
